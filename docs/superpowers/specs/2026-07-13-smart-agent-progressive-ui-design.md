# Smart Agent 渐进式界面设计

## 目标

降低用户在选课执行阶段的认知负担。现有页面把路径配置、计划生成、执行前
确认和执行后恢复同时铺在一页。改造后保留全部能力，但只在用户需要时展示
对应阶段的决策内容。

## 交互模型

页面调整为四步流程：

1. **确认数据**：确认当前个人课表，按需导入最新个人课表 JSON，导入目标
   课表。项目路径编辑移入设置抽屉。
2. **确认计划**：生成计划，审核待选课程、待退课程和高风险提示；用户可按需
   展开细节。
3. **执行准备**：运行安全检查，查看阻断原因，输入确认短语后生成手动执行
   启动包。页面不会直接启动 KillCourse。
4. **结果与替代方案**：人工执行 KillCourse 后解析日志，展示失败课程与可行
   替代教学班。后续的完整替代课表重算能力也放在这里。

系统根据已有数据自动定位当前步骤。用户可返回已经完成的步骤查看内容，但
只有满足本步骤前置条件后才能继续下一步。

## 信息层级

### 始终可见

- 紧凑顶部栏：当前学期、数据是否最新和一个符合当前步骤的主操作按钮。
- 四步进度导航。
- 当前课表、目标课表、待选、待退和保留课程的数量摘要。
- 当前步骤内的阻断提示和退课风险。

### 第一步：确认数据

- 当前课表摘要与最新个人课表 JSON 导入。
- 目标课表 JSON 导入。
- 简短路径状态；完整路径编辑仅在设置抽屉中显示。

### 第二步：确认计划

- 计划摘要与生成计划操作。
- 待选、待退清单；待退课程持续使用醒目的风险样式。
- 保留课程只显示数量。
- 当前/目标/保留课程、校验结果、计划解释、备选教学班和配置差异均放在默认
  收起的详情区。

### 第三步：执行准备

- 将“执行准备检查”和“Dry-run”合并为一个用户可理解的安全检查流程。
- 阻断原因、警告和命令行细节默认折叠。
- 显式确认短语和生成启动包操作。
- `config.json` 下载与写入是次要操作。

### 第四步：结果与替代方案

- 执行日志摘要。
- 失败课程的备选教学班及兼容性解释。
- 输出文件下载放在次要操作区。

## 隐藏与合并

后端接口和生成文件不删除，只调整默认可见性：

- 路径表单移入设置抽屉。
- 当前、目标、保留课程，校验、解释和配置细节默认收起。
- `action-plan.json`、`config.json`、原始 JSON 和文件下载统一放入详情/下载区。
- 日志解析与备选推荐在进入第四步前不显示。
- `action-plan.json` 自动写入以保留追溯记录；写入
  `HDU-KillCourse/config.json` 始终需要用户明确勾选。

## 安全规则

- 有阻断性校验问题的计划只能预览，不能生成执行配置。
- 包含退课时，授权前必须导入最新个人课表快照。
- 页面必须持续明确：安全检查和启动包生成不会真实执行选课或退课。
- 步骤切换和隐藏操作均不得隐式写入 KillCourse 配置。

## 兼容性与验证

既有 API、`action-plan.json`、KillCourse 配置生成、授权票据、启动包、日志解析
和备选推荐的数据格式保持不变。本次仅重构前端信息架构。

- UI 冒烟测试覆盖步骤导航、阶段操作、导入、计划生成、安全检查和结果区。
- 现有 Smart Agent 端到端测试继续覆盖计划、风险阻断、授权、启动包、日志与
  替代推荐。
- 使用桌面和移动端截图检查非当前步骤内容不会干扰页面，且文字不溢出。
