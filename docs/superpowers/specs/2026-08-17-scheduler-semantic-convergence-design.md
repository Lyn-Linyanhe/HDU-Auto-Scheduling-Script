# 主站课程约束语义收敛设计

**状态：** 已确认，进入实施阶段

## 目标

把主站中两套重叠的课程约束语义收敛为一个清晰模型：具体教学班通过 `lockedItemId` 锁定；已选但未锁定的课程仍然可以在候选方案中被替换或退选。删除用户可见的“必选”概念和教师软偏好，同时保留用户已经明确需要的时间硬约束、方案级联动和全天无课优先排序。

## 当前问题

- `requiredCourses` 是课程级文本约束，可以把一个课程名称解析成多个教学班候选；`lockedItemId` 是具体教学班约束。两者同时存在，界面容易让用户误以为它们是同一个概念。
- `preferredTeachers` 只通过评分影响排序，却以“偏好教师”出现在约束面板中，继续暴露了用户已经要求取消的软偏好概念。
- 现有 UI 验收验证了锁定和底板导入，但没有验证课程级约束区域的结构和“搜索后选择具体教学班并锁定”的行为。
- Smart Agent 的真实选退课、实时人数和行政班课表依赖外部项目或外部数据源，不能通过主站改动伪造为已完成。

## 设计决策

### 1. 唯一课程强制来源

`selectedGroups[groupId].lockedItemId` 是唯一的课程强制保留来源。

- 有 `lockedItemId` 的课组只能选择该教学班。
- 没有 `lockedItemId` 的已选课组保留 `null` 选项，允许候选方案退掉该课程。
- 个人课表、班级课表和用户手动锁定都使用同一条状态路径。
- 课程名称、课程号或实践类别搜索只用于找到候选教学班，最终必须落到具体 `item.id`，不能创建模糊的课程级必选组。

### 2. UI 收敛

课程级约束区域改为三部分：

- “已锁定教学班”：展示当前锁定项，并允许取消锁定。
- “从已选课程快速锁定”：对已经加入的具体教学班提供锁定操作。
- “搜索全体课程并锁定”：搜索结果按具体教学班展示，点击后执行加入并锁定。

左侧主课程搜索仍然保留；搜索结果中的“加入”按钮继续表示加入但不锁定。课程卡片和已选课表上的锁定入口保持一致。

### 3. 旧状态迁移

旧版本 localStorage 中的 `requiredCourses` 只在启动时作为一次性迁移输入读取，不再进入候选算法或新状态模型。

- 如果旧 token 能唯一匹配一个具体教学班，自动加入并锁定。
- 如果 token 匹配多个教学班或无法匹配，不做猜测，清除旧约束并显示“需要重新选择具体教学班”的提示。
- 迁移完成后不再保存 `requiredCourses` 字段；提示只保留到用户下一次修改或清除。
- 迁移逻辑使用纯函数，便于对唯一匹配、歧义匹配和未匹配分别测试。

### 4. 方案级约束与排序

删除“偏好教师”输入、状态映射、评分扣分和结果解释。保留：

- 排除教师作为硬过滤条件。
- 强制一起和教师一致作为方案级硬规则。
- 最多早八、午间压缩、晚课以及最少全天无课天数作为时间硬约束。
- 全天无课天数优先、时间负担和学分作为固定排序指标；结果页面称其为“排序指标”，不再称为软约束或偏好命中。

### 5. Smart Agent 边界

本阶段不把 Smart Agent 改成自动执行器。保留计划、diff、dry-run、人工授权票据、启动包和执行后日志解析；真实登录、实时课程查询、选课/退课、蹲课、实时日志和行政班课表继续标记为外部项目或外部数据源能力。

## 验收标准

1. 主站新状态和 DOM 中不再存在可操作的 `requiredCourses`/“必选”入口。
2. 搜索并锁定具体教学班后，该教学班出现在每个候选方案中；普通未锁定已选课仍可被移除。
3. 旧状态唯一匹配时能自动锁定，歧义或未匹配时不会静默选择错误教学班。
4. `preferredTeachers` 不再改变候选结果或排序，也不再出现在用户界面和结果解释中。
5. 强制一起、教师一致、时间约束、全天无课优先和个人课表自动锁定均保持通过。
6. 主站桌面和移动 UI 验收包含课程级约束结构与操作断言。
7. Smart Agent 的外部实时执行边界在文档和验收输出中保持明确。
