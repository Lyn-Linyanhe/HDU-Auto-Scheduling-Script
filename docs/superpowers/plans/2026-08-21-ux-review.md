# Smart Agent 用户体验测试分析（2026-08-21）

> 范围：这不是功能正确性测试，而是**使用体验**测试分析：从“一个真实用户第一次打开这个
> 工具、一步步把目标课表变成实际选退课”的视角，评估信息架构、反馈、引导、信任感、
> 错误处理与视觉细节。证据包括：全量验收 UI smoke（桌面 1440px / 移动 390px）、
> 页面截图（整页/桌面/移动）、对截图的关键帧复核，以及 `web/index.html`、`web/app.js` 源码走读。

## 1. 证据与方法

- 截图（本次验收生成，可复现）：`hdu-smart-agent-ui-smoke-44352/smart-agent-ui-{smoke,desktop,mobile}.png`
- 自动化断言（`scripts/smart-agent-ui-smoke.js`）已验证：无横向溢出、无控件重叠、无页面 JS 错误；
  课程详情含“容量/可选/第1轮/80 人”；容量摘要含“非实时/快照更新时间”。
- 方式：真实拉起 Smart Agent（当前代码，v0.5.9 视角）→ 加载 mock 课程库 → 桌面/移动双视口截图 →
  视觉复核 → 与源码交叉核对。

## 2. 做得好的地方

- **四步工作流清晰**：确认数据 → 确认计划 → 执行准备 → 结果与替代方案，顶栏步骤条 + 主操作按钮
  （“生成执行计划”）指路明确，首次用户不容易迷路。
- **关键数据状态一眼可见**：顶部状态格展示 course.json / personal-schedule / live / KillCourse /
  备选教学班五张卡，“可选缺失、未同步、已检测到”等信号配色清晰。
- **个人课表刷新体验成熟**：立即刷新 + 自动刷新开关 + 间隔秒数 + “来源/上次刷新/下次刷新”三格状态 +
  失败横幅“最近一次刷新失败（时间）：原因 已保留上次成功课表”，这是本项目里体验最好的一块，
  新功能全部沿用同一模式。
- **失败回退语义一致且诚实**：实时容量无数据时回退 course.json 快照，并明示“快照/非实时/时间”，
  不会把缓存谎报成实时。
- **新“刷新实时容量”按钮已出现在课程情报区**（整页截图可见），按钮自带 tooltip 解释受选课状态影响。

## 3. 截图复核结论

- **桌面 1440px**：整体对齐、留白均衡、无横向溢出/重叠；顶部状态区、左右分栏、底部课程情报
  层次清楚；课程情报主体在折叠线以下，需滚动（预期内）。
- **移动 390px**：无横向溢出、无遮挡；主要体验短板是**顶部工具按钮热区偏小**（打开主站/设置/刷新
  三键并排）与**四张状态卡两列排布偏挤**；课程情报控件区在窄屏下换行后仍可点，无遮挡。
- **整页**：结构完整；课程情报区在数据加载完成前显示“读取中/等待课程库”，此时“刷新实时容量”
  按钮已出现但数据区为占位文案，属正常加载态。

> 说明：视觉复核一度把“目标课表/教学班”读成繁体，已回源核对——源码全部为简体，该条不成立，
> 不列入问题。

## 4. 问题清单（按影响排序）

### P1（建议近期处理）

1. **首次失败但无实时快照时的文案不准**（已修复）
   - 原状：任何刷新失败都提示“已保留上次成功快照”，但首次使用根本还没有快照，实际是回退到
     `course.json`。
   - 已修：`renderCourseCapacityFailure()` 与按钮提示按 `source==='live'` 区分——
     “已保留上次成功快照” / “已回退本地 course.json 快照”。
   - 定位：`HDU-Smart-Course-Agent/web/app.js` 的 `renderCourseCapacityFailure`。

2. **“实时容量”可发现性低**
   - 它藏在“课程数据与教学班”区块底部，用户不会主动去找。
   - 建议：在顶部状态格新增一张“实时容量”卡（未刷新/实时 N 人/快照），点击直达刷新，参考
     现有五张状态卡交互。

3. **移动端顶栏按钮热区小**
   - “打开主站/设置/刷新”在 390px 下偏窄，容易误触。
   - 建议：窄屏下折叠成“更多”菜单，或图标 + 足够点击面积（≥44px）。

4. **命名一致性**
   - 个人课表用“立即刷新”，容量用“刷新实时容量”，动词不统一。
   - 建议统一为“刷新”+ 对象：“刷新个人课表”“刷新实时容量”；保留 tooltip 解释。

### P2（中期体验）

5. **多异步动作的状态消息互踩**
   - `statusMessage` 是全局单值，个人课表刷新与容量刷新并发时，后完成的会把前者文案覆盖。
   - 现状：已用 `liveRefreshError`/`courseCapacityError` 独立横幅分流失败信息；剩下“进行中/成功”
     短消息共用一个通道。可接受，但值得把每类操作的即时反馈独立化。

6. **“12 门 vs 10 门”之类的口径困惑（信任感）**
   - 界面上同时有“目标课表”数量、“课程库”数量、“当前个人课表”数量，来自不同数据视角，用户会困惑。
   - 建议：在各计数徽章旁加来源角标或 tooltip（目标课表=导入件；课程库=全校可选教学班视角；
     当前=本人课表），并保持实时容量数字与课程库口径一致。

7. **大课程库的渲染性能风险**
   - 本次 mock 有 4449 门课时，课程下拉/列表一次性渲染；数据量再大会卡。
   - 建议：下拉改用分区/懒加载或虚拟滚动；这是性能风险而非当前 bug。

### P3（细节）

8. 状态格在移动端两列排布偏挤，可考虑三列或单列。
9. “未同步”红色标签与“立即刷新”按钮之间没有快路径（如点击标签触发刷新）。
10. 加载态用静态占位文字而非骨架屏；体验合格但不够精致。

## 5. 结论

功能完整、反馈机制（尤其失败回退）诚实可靠，移动端无溢出，是能放心让人用的本地工具。
主要提升点集中在**可发现性（实时容量入口）、移动端触控热区、并发操作的信息反馈、与数字口径
信任感**四个方面。P1-1 已随本次提交修复；其余建议进入后期规划（见
`docs/superpowers/plans/2026-08-21-roadmap-multi-campus.md`）。
