# 全项目用户体验全面审核与改进计划（2026-08-21）

> **流程遵循客观要求**：①全面审核 → ②列改进方案 → ③对改进方案做审核 → ④实施方案并验证，
> 直到两套界面（主站“课表自动化编排助手” + 智能选课执行助手）达到可接受的体验基准。

## 0. 审核方法（证据链）

- 真实拉起两套程序，Edge 无头双视口截图（桌面 1440px / 移动 390px）。
- 几何断言（无横向溢出、无控件重叠、控件不出视口）+ 交互断言（容量/能力/步序/导出/收藏/删除/导入）：
  `scripts/smart-agent-ui-smoke.js`、`scripts/main-ui-acceptance.js`、`scripts/testlab-acceptance.ps1` 全链路。
- 源码走读：`web/styles.css`、`web/scheduler.js`、`web/scheduler.html`、
  `HDU-Smart-Course-Agent/web/{style.css,index.html,app.js}`。
- 视觉复核多次用视觉模型读图；对其中疑似“繁体错字”等项已回源核对，不入结论。

## 1. 全面审核发现

### 1.1 主站 · 课表编排助手（排课）

**UI 层**
- [x] 已修：按钮高度不统一（`.primary-btn/.ghost-btn` 只给了 padding，没有统一 min-height，
  小按钮 `.small` 也无高度 → 同一工具栏内按钮参差）。已统一：主按钮 38px、小按钮 32px。
- [x] 已修：顶栏三个操作按钮与各面板按钮高度对齐问题（同一规则覆盖）。
- [ ] 待办：顶栏长按钮“打开 HDU 智能选课执行助手”在更窄桌面可能折行，建议网格布局换行对齐
  （`align-items:center` + 固定按钮组高度）或缩写为“打开智能选课助手”。
- [ ] 待办：移动端顶栏/工具栏按钮热区偏小（390px 下多按钮并排）。

**使用逻辑层**
- [x] 已确认（做得好）：主站 subtitle 明确“N 个教学班，M 个课组”，已选课组面板逐组显示
  教学班数量——**主站的口径沟通是到位的**；12 vs 10 的困惑主要在智能助手的课程库计数单位不明确（见 1.2）。
- [x] 已确认（做得好）：导出按钮文案随预览状态联动（`renderAll` 里
  `保存为目标课表 / 保存当前课表`），导出地址/类型与文案一致。
- [x] 已确认：生成 0 方案时给出原因诊断（`renderDiagnostics`）；估算/生成都有 busy 守卫与
  明确的过程文案（“正在估算…/正在检查候选规模…/正在生成…”）。
- [x] 已修：候选数量超 500 的确认已从原生 `window.confirm` 改为应用内模态弹层
  （`#ux-confirm`，支持 取消/继续生成、Esc 关闭、焦点管理），与整站风格一致。
- [x] 已修：**“删除方案”此前不可单条撤销且“恢复”会全部重算**（`restoreDismissedCandidates` 重新调
  求解器，慢且顺序/结果可能变化）。现改为：**本轮生成结果做快照（`dismissedBackup`），删除只从
  列表移除；恢复=清空屏蔽集并回插快照，不重算求解器**（快、确定性高）。新一轮生成/清空会重置快照。
- [x] 已修：估算/生成失败改为“失败横幅 + 重试按钮”（`#scheduler-notice` + showNotice），不再只有一句话。
- [ ] 待办 P3：`importBaseSchedule` 对未匹配条目只记数字，建议列出未匹配项可点开。

## 3. 对改进方案的审核（自评）

- **采用**：A1、A2、A3 —— 纯样式/文案层，无行为语义变化，回归风险低，收益直接可见；已实施并验证。
- **采用（待实施，风险可控）**：A4 —— 行为改动但**不动求解器算法**，只改“删除/恢复”在内存列表上的
  撤销语义；需补 main-ui-acceptance 断言；风险=与旧 localStorage 状态的向前兼容（dismissed 集合仍在）。
- **采用（已实施 v0.5.11）**：A5、A6 —— UI 层替换与增强，不触碰求解正确性；
  main-ui-acceptance 新增 DOM 断言（`#ux-confirm`/`#scheduler-notice` 存在且默认隐藏）。
- **暂缓**：A7（两站移动端折叠菜单改动面大，收益集中在首屏工具栏；先做热区放大这一半近似于
  A1 的移动分支，折叠菜单并入 roadmap Phase 2）、A8（消息通道重构需动多处调用，先用现有双横幅，
  观察真实使用）、A9（依赖真实数据，已列入 roadmap Phase 3/选课期验证）。
- **否决/不单独做**：视觉模型曾报告“繁体错字”与“目标课表缺刷新按钮”——已回源核实前者不存在、
  后者是两栏信息架构差异（右栏无需刷新），不再处理。
