# HDU 课表自动化编排助手使用说明

## 文件说明

- `HDU-Auto-Scheduling-Script.exe`：统一启动入口，自动在课程导出页和离线排课页之间切换。
- `samples/course.sample.json`：测试用全校课程数据。
- `samples/personal-schedule.sample.json`：测试用个人课表底板。
- `COURSE_SCHEMA.md`：课程 JSON 的统一字段说明。

## 推荐使用流程

1. 运行 `HDU-Auto-Scheduling-Script.exe`。
2. 程序会检查输出目录是否已有 `course.json`。release 版输出目录默认为 exe 所在目录。
3. 如果全校课表可用，会直接进入 `HDU课表自动化编排助手`；如果同时有 `personal-schedule.json`，会自动作为已选底板导入并锁定。
4. 如果缺少全校课表，会进入课程导出页；在自动打开的浏览器页面中填写学号、密码、学年和学期。若密码直连被学校网关拦截，程序会自动切换到浏览器登录页，并填入本次输入的学号和密码完成登录后继续导出。
5. 导出成功后，exe 所在目录会生成：
   - `course.json`
   - `personal-schedule.json`
6. 导出完成后会自动跳转到排课助手，并把个人课表作为已选底板导入并锁定。若只想补导个人课表，可在排课页点击“导出/更新课程”回到导出页。

在排课页，加入课程和锁定教学班是两个独立操作：未锁定的已选课程可以在候选方案中被替换或退选；锁定后只保留指定教学班。课程级约束面板中的搜索结果始终对应具体教学班，点击“加入并锁定”即可固定该班次。旧版本保存的课程级约束只会在能唯一匹配具体教学班时自动迁移，存在多个班次时需要手动重新选择。

## 无法联网导出时

如果学校接口暂时不可用，可以先用 Excel 或 JSON 测试：

- 把任务落实课程导出的 Excel 放到 `HDU-Auto-Scheduling-Script.exe` 同目录，启动后会尝试自动转换 `course.json`。
- 或把 `samples/course.sample.json` 改名为 `course.json`，把 `samples/personal-schedule.sample.json` 改名为 `personal-schedule.json`，然后启动排课助手测试功能。

## 常见问题

### 浏览器没有自动打开

复制窗口里显示的本地地址，在浏览器中手动打开：

- 统一入口：`http://127.0.0.1:6789`
- 导出页：`http://127.0.0.1:6789/exporter/`
- 排课页：`http://127.0.0.1:6789/scheduler.html`

### 提示端口被占用

先关闭已经打开的旧窗口。如果仍然失败，打开任务管理器结束旧的 `HDU-Auto-Scheduling-Script.exe`。

### 自动登录

主站支持自动登录：没有登录会话时，会自动从 `login-config.json`（与 exe 同目录）或同级 `选课脚本/config.json` 读取账号密码，并在浏览器中完成登录后刷新个人课表。也可用环境变量 `HDU_LOGIN_CONFIG` 指定配置文件路径。

### 提示账号或密码错误

先确认学校统一身份认证能正常网页登录。如果网页能登录但导出器失败，可能是学校登录页或风控策略发生变化，需要更新导出器。

### 输出文件写到了哪里

release 版默认把课程、个人课表、目标课表和当前课表写入 `HDU-Auto-Scheduling-Script.exe` 所在目录。开发或测试时可以设置 `HDU_OUTPUT_DIR` 覆盖默认目录；主站读取也会使用同一个目录，不会出现“文件已导出但排课页读取不到”的分裂路径。

### 个人课表没有自动导入

确认 `personal-schedule.json` 位于输出目录。若已经手动导入过底板，程序不会覆盖你的本地选择。

### 生成候选方案太少

检查页面里的“没有候选方案”诊断说明。新版诊断会按锁定冲突、课程互斥、学分范围、教师条件、时间约束和方案约束分类，并给出下一步建议。常见原因包括锁定课冲突、学分范围过窄、时间级约束过紧，或者方案级约束要求过强。

如果你刚加入了两门课程级约束后候选变成 0，优先看是否出现“课程互斥”或“锁定冲突”。这通常表示两门课所有可选教学班都时间冲突，或属于同一课程号只能选一个。

### 候选方案详情怎么看

候选方案里的“排序指标”不是越高越好。排序会先看全天无课天数，全天无课越多越靠前；同等情况下排序指标越低越靠前。候选卡会列出底板变化、需退选课程、新增/替换课程、锁定课程和命中的方案级约束。

### 生成候选方案太多

增加约束条件，例如锁定具体教学班、排除教师、最多早八天数、最多晚课天数、最少全天无课天数，或添加强制一起/教师一致规则。

### 生成候选方案时页面是否会卡住

新版会优先把候选估算和生成放到浏览器 Web Worker 中运行。Worker 不可用时会自动退回同步生成，结果一致，只是页面可能短暂变慢。

## 分发包自检

从源码仓库生成 release 包后，可以运行：

```powershell
powershell -ExecutionPolicy Bypass -File scripts\release-main-smoke.ps1
```

该脚本会直接启动 release 包里的主 exe，并验证缺少全校课表、仅有全校课表这两个常见启动分支。

如果已经进入解压后的 release 包目录，也可以直接运行同一条命令；脚本会自动使用当前包里的 `HDU-Auto-Scheduling-Script.exe` 和 `samples/course.sample.json`。
